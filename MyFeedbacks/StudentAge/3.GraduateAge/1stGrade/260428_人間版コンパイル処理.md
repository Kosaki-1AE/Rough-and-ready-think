gcc → cpp → ccl → as → ld
- 入力 → 構造化 → 意味付け → 最適化 → 出力
- Cコード → AST（構造）→ IR（意味）→ 最適化 → アセンブリ（出力）
- ソースコード → バイトコード（中間表現）→ JVMで最適化（JIT）→ 実行
- 外部刺激（視覚・音）→ 認知（構造化）→ 意味解釈（感情・経験）→ 行動選択（最適化）→ 動作（出力）

ダンス版はこうなるっぽい：
音・空間・他者 → リズム分解（トークン化）→ 動作構造（AST）→ 意味付け（感情・ノリ）→ 最適化（ズラし・間・省略）→ 身体出力（モーション）


入力→構造(AST)→意味(成立するか＝整合性確認)→抽象(具体だけ削りまーす)→最適化(更に変形させまーす)→具体化(最適化されたものを機械語に変換しまーす)→統合
- 意味(Semanticと呼ばれるらしい)：形は正しい？何を意味する？
- 抽象(IRと呼ばれる)：何でもいいから意味を計算可能な変数に置き換えましょう！
- 最適化(Transform)：一番安定できるものに変換(計算してないなら計算する、代入してないなら代入するなど)
- 具現化(Lowering)：CPU語に変換〜。

意味以降が急にわからんくなる理由：関係性と制約のみの世界になるから(もっと言うと、状態と置換を扱ってんのね🈁)

これをどうにかできるらしいのが：意味保存・等価変換
1. 観測可能な結果が同じ
2. 副作用が同じ
3. メモリ状態が同じ
4. 例外・未定義の振る舞いも含めて同じ

人間の場合はどうなるかって言うと…
意味保存：確率的に許される範囲内の行動(それぞれが別途の意味の分布を持つ)

構造的なところはあるっぽいね
1. 構造（Structure）      → gcc的
2. 状態（State）              → 量子/人間的
3. 評価（Evaluation）    → AI的
4. 出力（Execution）     → 物理（ダンス）

可能性を定義し（gcc）、状態として保持し（量子）、評価で収束させ（AI）、身体で出す（人間）

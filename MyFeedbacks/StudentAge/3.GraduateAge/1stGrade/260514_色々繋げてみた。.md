となるとこれで行ける説？：Python → C → Assembly → Machine Code → Logic Gates → Transistor → 電子回路

なお…
- レジスタ＝＝現在状態
- ALU＝＝状態変換
- 命令＝＝次状態へのルール
- クロック＝＝状態更新タイミング
- メモリ＝＝長期保存
- CPU＝＝状態遷移器

現状のC-CPUの流れ：
Cコード → コンパイラ → Assembly → 機械語 → メモリ配置 → CPUがfetch → decode → execut → ALU/レジスタ → 論理ゲート → トランジスタ → 電子


おそらく8→2になるんだけど、2にするには基準点を固定する必要があるのよな。
となると恐らく言えそうなのが「順番を加味して1択とする」ってことなのよ。
今の量子コンピューティングってのは重ね合わせが確定せんとダメっていうことやんすか、だけど俺からしたら、「順番の優劣さえ確定すれば流れなんて余裕で確定するんだから、重ね合わせる以前の問題にならんか？」ってことなのよね。

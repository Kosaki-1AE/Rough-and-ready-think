# GBMC Minimal Core v0.1 — 最小確定実験

## 目的
巨大なLLMや学習済みモデルなしで、候補の区別・保持・確定を最小構成で実行できるかを検証する。これはGBMCCQSDの**概念から着想を得た独立した最小モデル**であり、16 Roomsの完全実装でも、音楽v0.8の移植でもない。

## 構成
- `minimal_core.py`: 候補集合の積集合による絞り込み。結果は HOLD / COMMIT / CONFLICT。履歴を記録する。
- `test_minimal_core.py`: 6つの単体テスト。
- `results.csv`: 2〜256候補を理想的な二分観測で絞る実験結果。
- `sample_history.json`: 1回の観測例。

## 実行
```bash
python minimal_core.py
python -m unittest -v
```

## 判定の仕様
- 新しい観測は「まだ可能な候補の集合」として与える。
- 候補が2つ以上残れば `HOLD`、1つなら `COMMIT`。
- 候補が0なら `CONFLICT`。状態は変更しない。
- 一度確定した状態を覆す矛盾した観測は `CONFLICT` として記録する。確定の取り消しや再開は未実装。
- 観測に未知の候補が混ざっていればエラー。

## 結果と限界
候補数が2のべき乗で、各観測が候補を半減させ、正解が候補に残ると仮定すれば、確定に必要な観測回数は log2(N) となる。これは既知の二分探索の性質であり、GBMC独自の新発見ではない。

この実験では意味の抽出、自然言語の解析、候補の自動生成、観測の真偽判定、曖昧な情報の確率的扱い、16 Roomsの制御は実装していない。「人間の判断がこの仕組みだけで説明できる」ことも示していない。

## 次の検証
同じ条件を日本語・英語・Python・Cの限定構文で表現し、各入力を共通の条件式に変換した上で同じHOLD/COMMIT/CONFLICTが出るかを比較する。その際は各言語のパーサと正解データを独立に準備する。

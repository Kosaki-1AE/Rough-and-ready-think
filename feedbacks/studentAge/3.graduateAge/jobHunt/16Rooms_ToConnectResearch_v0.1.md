# 16Rooms研究計画・統合まとめ v0.1

- 作成日：2026年11月5日
- 状態：議論の整理・予備実験設計案（未検証）
- 基礎資料：`16Rooms_formation_trace(3).md`（Feedbackから16Roomsへの形成過程：一次資料トレース〈暫定版〉）

> **中心方針**：16Roomsを正解として人間の判断を当てはめるのではなく、人間の判断・選択・保留・更新を観測し、そのデータから16Roomsに相当する構造が再現されるかを検証する。

## 1. 背景：Feedbackから16Roomsへ

基礎資料に記録された形成過程は、概略として次のように整理できる。

1. **Feedback**：自己省察・経験の継続記録。
2. **予測・現実・ズレ**：経験の結果が次の入力の受け取り方を変えるという更新ループ。
3. **処理・履歴の整理**：観測、選択、操作、更新、処理確定と履歴再利用。
4. **16Roomsの構想**：2026年10月15〜16日に処理確定機構として明示。
5. **構造の再検討**：10月26日に固定的なRoom役割を見直し、27日以降に4×4構造などを検討。

この記録から言えるのは、**16Roomsが観察・省察・概念整理を通じて形成された理論案である**ということ。独立した被験者データから16状態が実証されたわけではない。

## 2. 研究目的と問い

### 目的

ダンサーが音楽を受けて技を構想・選択・保留・変更する過程を記録し、文脈・履歴・干渉に依存する判断規則を抽出する。その結果と16Roomsを比較し、説明力・予測力・再現性を検証する。

### 研究問い

- RQ1：技の選択順路には、単純な出現頻度や直前の選択だけでは説明できない法則性があるか。
- RQ2：音楽条件が変わると、判断規則や選択順路はどのように更新されるか。
- RQ3：上級者は技が異なっても、選択を成立させる判断基準に共通性を示すか。
- RQ4：16Roomsは、より単純な状態モデルに比べて、判断過程をよく説明・予測できるか。

### 中心仮説（未検証）

> 人間の選択・判断過程には、単なる候補の出現頻度では説明できない、文脈・履歴・干渉に依存した遷移の法則性が存在する。

> 熟練者は、異なる技や順路を選んでも、その選択を成立させる判断基準が似ている可能性がある。

## 3. 概念の区別と固定・可変要素

**Room（処理構造）≠ 役割ラベル（判断・動作の機能）≠ 選択肢（具体的な技）**。

| 項目 | 暫定方針 |
|---|---|
| 16個のRoom | 比較対象となる仮説モデルとして保持 |
| GBMCCQSDの8ラベル | 役割の候補として保持。ただし被験者への提示は誘導に注意 |
| Roomの個別役割 | 最終確定しない。10月26日の「Roomには役割を定義しない」を尊重 |
| 技の種類・候補数 | 可変。自由追加・削除・重複・保留を許す |
| 初期候補の分布 | 実験で測定 |
| 遷移順序・バイパス条件・遷移コスト | 実験で推定・比較 |
| 識別不能 | 無理に分類せず記録 |

資料には10月16日時点のRoom名と役割案も残っているが、後日の再検討を踏まえ、**その役割案を実証済みの定義として扱わない**。

### ダンスの8役割（資料に記録された対応）

| 3bit | 記号 | 役割 |
|---|---|---|
| 000 | G | 置く |
| 001 | B | 止める |
| 010 | M | 当てる |
| 011 | C₁ | 乗る |
| 100 | C₂ | 外す |
| 101 | Q | 打つ |
| 110 | S | 強制停止 |
| 111 | D | 弾く |

技そのものと役割は一対一対応とは限らない。同じウェーブでも、文脈次第で「乗る」「当てる」など異なる役割を担いうる、というのが実験上の仮説である。

## 4. 実験の基本方針：まずはアンケート

身体動作解析や3D再生を最初から実装しなくても、**自己申告による判断過程の予備データ**は収集できる。ただし、アンケートは無意識の内部状態を直接観測する手段ではない。

### 予備実験案

- **対象**：経験者と初心者を含むダンサー6〜10人程度（設問の動作確認を目的とする便宜的な規模）。
- **刺激**：共通の短い音楽区間。通常版と、アクセント・展開などを変更した版。
- **条件**：まず「音楽のみ」を基本とし、参考映像を使う場合は別条件として扱う。
- **回答方式**：最初の候補・理由は自由記述を優先。選択肢は補助的に用意し、自由追加を認める。

### 実験手順

1. 共通の音楽を聴く。
2. 最初に思いついた技と、後から思いついた候補を順番に記録する。
3. 技を選び、並べ替え、構想した実行順路を作る。
4. 各技の役割、選択理由、選ばなかった候補とその理由を記録する。
5. 音楽の条件を変更して再度判断する。
6. 維持・変更・保留した箇所と、その理由を記録する。
7. 可能であれば回答の操作履歴・時刻も保存する。

**注意**：初めから8役割を見せると回答が誘導される可能性がある。自由記述を先に取得し、ラベル付けは後段に回す方法も比較する。

## 5. 必要なデータ

| 分類 | 記録内容 | 主な目的 |
|---|---|---|
| 被験者属性 | 経験年数、主ジャンル、自己評価など | 熟練度・個人差の比較 |
| 刺激・条件 | 音源ID、再生区間、変更点、提示順序 | 条件の統制 |
| 候補生成 | 最初に思いついた技、追加候補、生成順 | 初期分布・候補生成規則 |
| 選択結果 | 実行したい技、順番、タイミング | 選択系列の分析 |
| 役割 | 8役割候補、複数ラベル、未分類 | 具体技から抽象役割への整理 |
| 判断理由 | 選択・不選択・変更・維持の理由 | 判断規則の比較 |
| 成立状態 | 実行したい／可能だが選ばない／成立扱い／不成立／不明 | 成立許可と実行可能性の区別 |
| 履歴 | 追加・削除・順序変更・保留・確定 | 遷移の追跡 |
| 時間・コスト | 判断変更までの時間、変更負担・維持負担の自己評価 | 遷移コストの仮説検討 |

**重要な区別**：

- 「実行できない」と「実行できるが選ばない」は異なる。
- 「実行した」と「実行せず成立したとみなす」は異なる。
- 「不成立」と「識別不能」は異なる。
- 遷移するコストと、遷移しないことによるコストは別々に扱う。
- 回答操作にかかった時間は、内部の判断時間そのものとは限らない。

### 最小限の回答ログ例（架空）

```text
participant_id: P01
stimulus_id: MUSIC_A
condition: original
first_candidate: wave
candidate_sequence: [wave, hit, freeze]
planned_sequence: [wave, freeze, hit]
role_sequence: [乗る, 止める, 当てる]
reason: 流れを保ち、次のアクセントを強調したい

condition: modified_accent
changed_sequence: [wave, hit, freeze]
change_reason: アクセントが前倒しになったため
withheld_candidate: freeze
withheld_reason: この位置では流れを止めすぎる
```

## 6. 16Roomsで特に検証したい現象

### 6.1 条件付き遷移

同じ技・同じ直前の選択でも、音楽条件や履歴が異なれば次の判断が変わるか。

### 6.2 成立許可とバイパス

実際に実行・確認していない段階を、どの条件なら「成立した」とみなすのか。バイパスを単なる省略と混同せず、**成立を許可する条件**を記録する。

### 6.3 保留と識別不能

決定できない場合、候補を保持する場合、観測上区別できない場合を無理に同一視しない。

### 6.4 履歴依存・フィードバック

過去の選択や結果によって、次の候補生成・条件解釈・判断理由が変わるか。

### 6.5 遷移コスト

変更する負担と、変更しない負担が、判断に異なる影響を与えるか。時間や自己評価は代理指標であり、内部コストの直接測定ではない。

## 7. 分析計画

1. **記述統計**：初期候補の頻度、候補数、変更回数、保留率、技・役割系列の分布。
2. **一致・類似性**：技そのもの、役割、判断理由、条件変更への反応を別々に比較。
3. **熟練度比較**：上級者同士／初心者同士／群間の共通性を比較。少人数では探索的な結果に留める。
4. **予測モデル比較**：候補頻度のみ、直前の選択のみ、条件・履歴を含むモデルを比較。
5. **構造モデル比較**：8状態、固定16Rooms、4×4、可変状態数などを競合モデルとして評価。
6. **外部検証**：別の曲・別の被験者に対する予測性能を確認。

考え方の一例：

\[
P(r_{t+1}\mid r_t,h_t,c_t,u)
\]

ここで、\(r_t\) は仮説上の状態、\(h_t\) は判断履歴、\(c_t\) は条件、\(u\) は個人差を表す。**Room状態をどう観測データから推定するか自体が未解決の研究課題**である。

**16Roomsの妥当性を示すには**、既存モデルよりも予測・説明に役立つこと、状態の区別が再現可能であること、後付けのラベル付けだけで説明できてしまわないことが重要。

## 8. AIST++・動作アプリ・MediaPipeの位置付け

- **アンケート**：判断・理由・変更履歴を収集する最初の手段。
- **AIST++など**：技の候補映像・動作素材として利用を検討する。完成済みの振付データを技単位に切り出す作業が必要。
- **動作配置アプリ**：候補の追加・並べ替え・再生・操作履歴の保存を実現する将来の拡張。
- **MediaPipeなど**：実際に踊った場合の身体動作を測る補助的手段。判断理由そのものは測定できない。

当面は、**大規模な動作解析システムを作る前に、回答から判断過程をどこまで復元できるか**を確認する。

## 9. 検証済み・未検証の境界

### 資料・議論から整理できたこと

- Feedbackから16Roomsに至る構想の時系列が記録されている。
- 候補、条件、選択、履歴、成立許可、保留、遷移コストが観測候補として挙がっている。
- 8役割ラベルと16Roomsの区別が必要である。
- アンケートを用いた予備実験の設計が可能である。

### まだ実証されていないこと

- 人間の判断に本当に16個の独立した状態が必要であること。
- 16Roomsが他の状態数・構造より優れていること。
- 上級者に共通の判断規則があること。
- 自己申告から無意識の内部処理やバイパスを一意に同定できること。
- ダンス以外の領域でも同じ構造が成立すること。

## 10. 直近の実行順序

1. アンケートの設問と回答形式を確定する。
2. 音楽の通常版・条件変更版を準備する。
3. 自分で回答して、候補・理由・保留・変更が記録できるか確認する。
4. 少人数のダンサーに予備回答してもらい、設問の誘導や曖昧さを修正する。
5. 技・役割・判断理由の一致と、条件変更に伴う差を分析する。
6. その後、16Roomsを含む競合モデルの比較へ進む。

## 11. 研究概要（暫定）

> 16Roomsは、人間の判断過程を整理する中で形成された理論モデルである。本研究では、ダンサーが音楽に応じて動作を構想・選択・保留・変更する過程をアンケート等によって記録し、判断の文脈依存性・履歴依存性・条件変更への応答を分析する。抽出された判断規則を16Roomsおよび代替モデルと比較することで、16Roomsの説明力、再現性、適用範囲を検証する。

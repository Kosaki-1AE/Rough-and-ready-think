下に向かっていくにつれ中身の説明っていうことにしてますわ。
```c
chown()
{
		register *ip;
  
        if((!suser() || (ip = owner()) == NULL)
                  return;
        ip->i_uid = u.u_arg[1].lobyte;
        ip->i_gid = u.u_arg[1].hibyte;
        ip->i_flag =| IUPD;
        iput((ip);
}

owner()
{
     　　register struct inode *ip;
    　　 extern uchar();

        if ((ip = namei(uchar, 0)) == NULL)
                 return(NULL);
        if(u.u_uid == ip->i_uid)
                 return(ip);
        if (suser())
                 return(ip);
        iput(ip);
        return(NULL);
}

suser()
{
		if(u.u_uid == 0)
				 return(1);
		u.u_error = EPERM;
		return(0);
}
```
- `EPERM`：**E**rror: **PERM**ission(パーミッションエラー)の略。同じようなもので、`ENOENT`(**E**rror: **NO** **ENT**ry(ファイルが存在しない))、`EACCES`(**E**rror: **ACCES**s(アクセス権限がない、`EPERM`と近いが少しニュアンスが違う))、`EEXIST`(**E**rror: **EXIST**s(すでに存在している))がある。
- `i_uid`：i(所有者)`_UID`(**U**ser **ID**)、つまりは管理をする所有者のIDを指定するってことね
- `u.u_arg`：u(現在実行中プロセスの状態を保持するuエリア構造体の実体そのもの).u_arg(システムコールに渡された引数を保持するフィールド)

ちなC言語とUnixの仕様とが混ざってるので書いておくと.....C言語の仕様(=言語そのものに元から備わっている機能)
- 構造体を定義できること(`struct { ... }`)
- `.`(ドット)でメンバーにアクセスできること(`u.u_arg`)
- `->`でポインタ経由でメンバーにアクセスできること(`ip->i_uid`)
- グローバル変数を定義できること
んでUnixはというと.....Unixカーネル開発者たちが決めた「ルール」(=言語仕様ではない)
- `i_uid`のようにフィールド名の頭に`i_`をつける
- `u_arg`のように`u`構造体のフィールドには`u_`をつける
- グローバルな唯一の実体には`u`という変数名をつける

とりあえずオペレーティングシステム特論はこれをもとに書いていこうかと思いますー。

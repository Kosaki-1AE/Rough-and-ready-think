- 興味 = カメラを向ける方向の発生
- 候補分布 = 見える可能性のある視点群
- 認識エントロピー$H$ = 視点候補の散らばり
- 観測 = 実際に1つの視点から入力が来る
- 予測誤差$ε$ = 予想していた見え方と実際の見え方のズレ
- ベイズ更新 = 視点候補の重み更新
- 世界観距離$Δx$ = 認知カメラの座標変換量
- $ΔH$ = 視点候補の不確実性変化
- 影響度評価 = その視点移動が自分の世界モデルに与えた重み
- 信用 = 次にどこが見えるか予測できること
- 信頼 = 視点がズレても戻れること自由度 = 安全に動かせる視点

- ノリエントロピー = ズレた視点同士から意味が生成されること
- アトラクタ = 何度も戻る安定視点
- 責任の矢 = 他者の視点移動量まで背負うベクトル
- 世界観 = 安定した認知座標系

なおこれも言える模様：
- いじり = Δx + 帰還経路あり
- いじめ = Δx + 帰還経路なし
- ハラスメント = Δx超過が継続
- 夫婦漫才 = 大きいΔxでも共有座標系で復元可能
- RSD = 小さい入力でも主観的Δxが過大化
- ストレス嘔吐 = ΔxまたはdH/dtが耐久可能性Dを超過
⇨ 入力によって認知座標系がどれだけ動かされ、その移動を復元できるか

必要変数はこれ：
- $Δx$：視点移動量
- $H$：候補の散らばり
- $ΔH$：不確実性変化
- $R$：復元可能性
- $D$：耐久可能性
- $C$：コヒーレンス

責任量 = 相手の $Δx$ を復元可能範囲に収めるために提供する補助情報量

Git的なもの(認知座標変換の履歴管理)×Linux GUI(その履歴を操作・可視化する画面)＝認知のGit + 認知のGUI
対応版：
- commit = 世界観の保存点 / 3D空間上のノード
- diff = $Δx$ / ノード間ベクトル
- branch = 別の解釈ルート / 分岐線
- merge = 複数の世界観の統合 / 線の合流
- conflict = 解釈衝突 / 認識エントロピー増大 / ノードの揺れ・赤点滅
- checkout = 過去の世界観に戻る
- rebase = 過去の経験の意味づけ変更
- log = 感情ジャーナル / 認知履歴
- worldview = 現在カメラ位置

要求仕様：
- どのshellでも動く
- 環境変数を汚さない
- WSL / Ubuntu / macOS / terminal差を吸収
- P2P的に同期できる

基本設計：
単一バイナリ + ローカル設定ファイル + 明示コマンド

絶対避けなあかんこと：
- export PATH=...
- .bashrc編集
- .zshrc編集
- 環境変数必須
- Python venv必須
- Node/npm必須
- 常駐デーモン必須

実装：
- 言語：C
- ビルド：CMake
- 設定：./.cogit/config.json
- 保存：./.cogit/objects/
- 通信：libp2p or UDP/TCP自作は後回し
- GUI：raylib or freeglut

使い方イメージ：
./cogit init
./cogit commit memo.txt
./cogit log
./cogit diff HEAD~1 HEAD
./cogit view
./cogit sync peer-address
